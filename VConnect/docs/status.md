# VConnect status

## Implemented
Responsive social website with locally licensed Nunito. Dedicated responsive login/register routes, password visibility toggle, inline auth errors, submit/loading states, consistent original SVG navigation, authenticated feed without promo hero, motion-reduced swipe animations and distinct demo card palettes. Node.js 24 HTTP backend with SQLite at .local/vconnect.sqlite (ignored), prepared SQL statements, foreign keys and WAL. Registration/login/logout, scrypt password hashes with random salts, hashed server session identifiers, seven-day HttpOnly SameSite cookies, production Secure cookies, origin checks on mutations, body size limits and per-IP request/auth throttling. Profile editing, website/Twitch/YouTube/social link collection with HTTP(S) validation, cross-account feed, account-specific likes/bookmarks/swipes and persistence. Guest demo swipes are temporary. Six fictional labeled demo profiles, enabled for local development; production disables them by default. No fabricated follower counts or bot activity. Demo profiles never authenticate or simulate mutual matches. No tokens in frontend storage, logs or SQLite; only session hashes are stored. No shell/process/path API exposed to web content.

## Automated-tested
npm run check, npm test, npm run build. Store integration tests cover account registration, login rejection, password hashing, session hashing/expiry lookup, ownership, anonymous write rejection, unsafe URL rejection, posts, per-account interactions, swipe reset, SQLite reopen persistence, logout and production-default demo exclusion. HTTP smoke checks are documented in delivery. Browser QA observed dedicated /login and /register pages, successful local test-account registration, logout and subsequent login, demo swipe advancing to the next card, and a saved demo appearing in Connections. Login layout was visually inspected. HTTP smoke checks verified all auth routes, six labeled demos, guest state and cross-origin mutation rejection (403). Mobile CSS implemented but not checked on a physical device.

## Game-tested
Not applicable; no Minecraft/native/mod changes.

## Release readiness
Local implementation; no public deployment. Git delivery is recorded in the repository and delivery message. Not yet ready for public launch: email verification and password recovery, moderation/reporting, account/data deletion, legal/privacy content, backups and deployment with HTTPS still required. No image uploads, real-time messaging, mutual matches or notification delivery. .local and secrets must never be committed. This website does not require a Hera Windows updater release. Sites static hosting cannot run this Node/SQLite backend; deploy to a persistent Node host with a durable disk. The UI is no longer a browser-local data demo.
