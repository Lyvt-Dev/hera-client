# Hera development

Keep native filesystem, credentials, networking and process access behind typed Rust commands. Never expose arbitrary shell commands or paths to web content. No account tokens in React, logs or SQLite. Profiles use generated UUID directories. Only mark a Minecraft adapter supported after installation AND authenticated gameplay have been observed on each claimed platform. Document implemented, automated-tested and game-tested separately in docs/status.md. Run npm run check, npm test and npm run build after TypeScript changes; cargo test/check for native changes and Gradle build for mod changes. Do not invent social data or advertise unimplemented controls. All third-party code/assets require license review. No copied reference implementation.

Owner release preference: push validated implementation changes to https://github.com/Lyvt-Dev/hera-client and deliver versioned Windows releases for the updater. Keep normal user flows free of development notes and app-registration instructions; owner configuration belongs under advanced settings. Never commit or upload signing private keys, access tokens, local game data, or `.local/`. Document any blocked push or release accurately rather than claiming it was published.
